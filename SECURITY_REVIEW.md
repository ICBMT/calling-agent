# Milestone 2 — final implementation and security review

**Reviewed:** November 10, 2026  
**Scope:** Laravel provider configuration/control plane, four read-only discovery adapters, organization/platform authorization, normalized catalogs, and server-side routing. This is a source review plus local adversarial regression testing, **not an independent penetration test or production certification**.

**Decision:** the scoped implementation review is complete after the fixes below. **Authenticated live-provider acceptance remains open; M2 must not be marked unconditionally closed or voice-ready.** M3 has not started.

## Five requested guarantees

| Requirement                                                                                   | Review result and boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API keys do not leak into frontend responses, application logs/exceptions, or browser storage | Confirmed for the implemented application paths and regression cases. Keys are encrypted at rest, hidden from ordinary serialization/debug output, never repopulated/flashed, and excluded from responses/audits. Provider-route unexpected exceptions are generic even with debug enabled and log only an exception class. Browser checks inspect responses and application storage. See the operational boundary below; this is not a promise about compromised browsers/hosts or external request recorders.                        |
| Every provider operation enforces organization-level authorization                            | HTTP reads/setup/comparison and resource operations enforce membership-derived scope. Mutations and tests independently authorize in services. Every public routing method now requires an explicit actor and checks current organization membership **before querying/decrypting provider records**, including shared inheritance. Platform management has a separate, persisted operator permission and cannot access arbitrary tenants. Low-level adapters/transport are trusted server-only primitives, not user-facing endpoints. |
| Real documented endpoints with correct error/timeout/rate-limit behavior                      | Confirmed against official API documentation and isolated protocol tests. Only fixed HTTPS read-only endpoints are allowed. TLS, time/size/pagination limits, blocked redirects, safe status/error normalization, no automatic retries, and application throttles are enforced. **No authenticated live success is asserted.**                                                                                                                                                                                                         |
| Model/voice compatibility follows verified capabilities                                       | Account-returned IDs are intersected with reviewed exact official mappings where capability metadata is absent; other adapters use documented provider metadata. Current mappings are rechecked at selection/resolution, not merely at discovery. Retired, unknown, expired, incompatible, or malformed choices fail closed. This verifies catalog-level compatibility, **not paid inference entitlement or working audio**.                                                                                                           |
| Defaults/fallbacks cannot select incompatible capabilities                                    | Both paths apply identical eligibility checks for exact provider/category/model/voice, current credential version, freshness, enabled/key state, and expiry. ## Findings fixed during this review

1. **Explicit resolver authorization.** `ProviderManager` previously depended on trusted callers supplying an organization. `resolve`, `resolveNativeRealtime`, and `resolveModularPipeline` now require a `User` actor and authorize current membership before any provider lookup/decryption. Existing callers were updated; unauthorized members of other organizations and platform operators cannot resolve a foreign organization.
2. **Unexpected-exception boundary.** Expected adapter errors were already normalized, but unexpected credential-route failures could otherwise fall through Laravel's normal debug renderer/reporter. `ProviderExceptionBoundary` now covers both provider route families, suppresses raw exception messages/chains/context in application logs, returns generic no-store HTML/JSON errors, and preserves only numeric rate-limit headers. Normal authentication/validation behavior and secret `dontFlash` remain. Bootstrap turns off exception argument capture; sensitive service/DTO parameters have a second layer of PHP masking.
3. **Complete normalized-metadata secret guard.** IDs/names were already screened, but syntax-valid language metadata and numeric allowance/balance values needed an additional reflection check. All core adapters and the connection-test persistence boundary now reject normalized metadata containing the current key, including numeric values/keys and unexpected objects. Unknown failure reasons are allowlisted to safe categories. Credential JSON/debug output is always redacted; PHP serialization is prohibited.
4. **Current permissions for late results and platform operations.** A connection test rechecks the persisted initiating actor before applying results; membership removal, downgrade, user deletion, or operator revocation makes the result discarded. Platform policies and creation use current persisted permission, not a stale `User` object's flag. Unauthorized service tests are rejected before acquiring the connection-test lock or sending HTTP.
5. **Fail-closed compatibility metadata.** Catalog validation rejects malformed lists, absent selections/capabilities, impossible shutdown dates, and invalid/expired voice timestamps. Gemini rejects unsupported adapter categories and permissive relative/impossible expiry strings. ElevenLabs rejects malformed tier restrictions, unknown safety/category values, invalid alpha-access metadata, and unverified professional/high-quality compatibility rather than treating them as unrestricted.
6. **Retired model removed; cached mappings rechecked.** The official [GPT-4.1 nano page](https://developers.openai.com/api/docs/models/gpt-4.1-nano) reports **Shut down**. `gpt-4.1-nano` was removed from the exact map; no shutdown date was invented. Withdrawn/reclassified mappings or removed built-in voices immediately block an old catalog's selection/resolution even before its 24-hour expiry.
7. **Wrapped size-failure classification and meaningful option coverage.** Laravel can wrap a Guzzle size-guard exception in `ConnectionException`. The transport now recovers only its own safe category/status through either wrapper, discarding the raw chain. Size callbacks are exercised explicitly. The existing timeout/TLS/no-redirect option test was corrected to observe the actual request options (an unused standalone pending-request callback was not evidence of them).

No successful connection or provider catalog was inserted into the running workspace to make these checks pass. All successful protocol fixtures are isolated automated test data.

## Endpoint and transport audit

All requests below are server-side `GET` requests; no inference, synthesis, session-token, or telephony endpoint is called.

| Adapter       | Fixed discovery endpoints                                                                | Authentication                                                              |
| ------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| OpenAI        | `https://api.openai.com/v1/models`                                                       | `Authorization: Bearer …`; optional documented project/organization headers |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/models`, `/v1beta/voices`              | `x-goog-api-key`; models use camelCase pagination, voices use snake_case    |
| Deepgram      | `https://api.deepgram.com/v1/projects/{validated UUID}`, `/models`, optional `/balances` | `Authorization: Token …`; authenticated project ID must match               |
| ElevenLabs    | `https://api.elevenlabs.io/v1/user/subscription`, `/v1/models`, `/v2/voices`             | `xi-api-key`; public model availability alone is never authentication proof |

Enforced limits: TLS verification; no redirects/cookies/custom origins, paths, or query keys; no keys in URL tokens; 3-second connection and 8-second request caps, 25-second multi-request budget; 2 MiB response cap; at most five pages and 1,000 list entries; no automatic retry. Tests are throttled to 5/user/minute and 15/scope/minute, writes to 30/user/minute. Scope database locks, a per-configuration test lock, credential versions, optimistic revisions, and run tokens guard competing/stale writes.

401/invalid-key, 403/permissions, quota, 429/rate limiting, missing resources, provider 5xx, redirects, network/timeout, malformed/non-200 success, oversized responses, and pagination failures have distinct safe handling. Optional denied Deepgram balance read is explicitly unavailable, not invented and not mistaken for failed project authentication. A failed current check removes catalog eligibility. Upstream retry guidance is not automatically scheduled: connection tests do not auto-retry or manufacture an ETA.

## Compatibility and routing audit

- OpenAI uses documented model-specific dedicated-TTS voices separately from the ten Realtime voices. Existing TTS/transcription shutdown dates are enforced, using the earliest documented/reported date.
- Gemini Live accepts discovered prebuilt voices only. Dedicated TTS custom-voice support is model-specific; custom expiries are normalized from valid RFC 3339 timestamps and checked again at resolution.
- Deepgram uses the authenticated project's separate STT/TTS metadata; Aura's model ID already identifies its voice. Streaming/language metadata is not extrapolated across models.
- ElevenLabs requires explicit TTS capability; applies account tier and safety restrictions; requires model-specific professional fine-tuning / high-quality base-model support. Account allowances are snapshots, not Voca-attributed usage.
- Models without speech cannot accept a voice. Speech requires the voice in both that model's compatible IDs and the returned/documented voice catalog.
- An unhealthy local default can use only the explicit compatible local fallback, never silently a platform credential. Without a local default, the platform pair can be inherited by an authorized organization's server-side consumer. A lone local fallback is not a local override.
- Key/project changes invalidate evidence, usage, selection, and routing. A missing saved model/voice is reported as unavailable, not silently replaced. Routing never supplies missing modular stages from a native-realtime configuration.

This does **not** yet validate a combination's language, codec/sample rate, actual streaming behavior, interruption semantics, quota, inference permission, voice consent, or generated-audio quality. Those requirements remain activation/worker acceptance gates; there is no operational voice engine to certify in M2.

## Secret-handling operational boundary

The intended new key necessarily exists transiently in the password input and the HTTPS form submission while its authorized owner enters it, and in server memory while authenticating to its provider. Stored keys are not sent back to the browser. Application code does not put them in localStorage, sessionStorage, IndexedDB, CacheStorage, service workers, cookies, URLs, audits, or logs. Browser regression checks inspect these application-controlled paths after save/rotation/deletion; password fields are empty after validation and on subsequent pages.

An absolute “never under any circumstances” promise would be false: a browser extension/password manager, a compromised browser/server, a developer manually logging a request, a secret pasted into a non-secret field, or a reverse proxy/APM collecting bodies/headers is outside these code-level safeguards. The form explicitly warns against secrets in connection names. No external request recorder/APM is installed in this repository.

Deployment prerequisites remain **HTTPS**, `APP_DEBUG=false`, secure session cookies, restricted filesystem/database/backup access, protected and recoverable `APP_KEY`, and `zend.exception_ignore_args=On` in host PHP configuration as well as bootstrap. Do not enable raw request/body/header logging; redact `api_key`, `Authorization`, `x-goog-api-key`, `xi-api-key`, and credential payloads in any future proxy or monitoring integration. An encryption cast does not protect against a host compromised with both the database and application key.
