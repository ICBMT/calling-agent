# Milestone 3 — staged browser voice implementation

**Started:** November 10, 2026. M2 is now **locally approved by the user**; its authenticated real-account acceptance remains unverified. This milestone has permission to proceed, not a waiver of real spoken acceptance. Telephone calling is explicitly out of scope.

## First vertical slice

Browser microphone ⇄ LiveKit WebRTC room ⇄ independently running Python LiveKit Agents worker ⇄ OpenAI Realtime WebSocket API. Laravel carries no continuous media. Use the provider-owned OpenAI plugin with the saved M2 key, not LiveKit Inference credentials/billing and not a prerecorded response.

Keep native realtime distinct from modular STT → LLM → TTS. Stage one exposes only the documented OpenAI Realtime model family implemented by its worker. A modular boundary remains separate; do not expose unimplemented combinations as working. Do not expand media providers before recording one genuine two-way spoken browser conversation.

## Application boundaries and directory plan

- `app/Services/Voice/`: immutable session preparation, M2 resolution, room-scoped JWTs and fixed-path LiveKit API calls, worker claim/event authorization, safe status transitions, expiry/termination.
- `app/Http/{Controllers,Requests,Middleware}/`: authenticated/CSRF-protected owner/admin playground operations; independently HMAC-authenticated server-only worker routes. Browser never receives permanent provider or LiveKit API secrets, claim tickets, or application encryption keys.
- `app/Models/VoiceSession.php`, `database/migrations/*voice_sessions*`: organization/actor/agent-scoped session lifecycle and encrypted immutable configuration snapshot, version pins, hashed one-use claim ticket, bounded telemetry, expiry. This is browser-session metadata, not a telephone call record.
- `resources/js/workspace/voice/`: real LiveKit SDK lifecycle, microphone/remote audio, generation/cancellation guards, bounded transcript rendering with escaped text, controls, measured transport stats and honest state/errors. No recordings, tokens, or transcript persistence in browser storage.
- `resources/views/workspace/playground.blade.php`: saved draft and supported provider/model/voice/language choices, explicit AI/session disclosure, setup blockers, genuine streamed transcript, controls and diagnostics. Retain the separate local-only device check.
- `voice-worker/`: pinned Python dependencies and lock, typed session contract, authenticated Laravel client, per-job realtime model/session factory, events/metrics, lifecycle watchdog and safe logging, independent unit/protocol tests. No Laravel DB or APP_KEY access.
- `tests/Feature`, `tests/Browser`, `voice-worker/tests`: control-plane isolation/security/state-machine tests, browser lifecycle/error/permission tests, actual SDK API compatibility checks, and explicitly gated live acceptance instructions.

## Database and authorization design

A browser session has an opaque UUID, organization and initiating user, saved draft reference, requested language/architecture, encrypted immutable instructions/configuration snapshot, provider IDs/credential versions, room/participant identities, state/error code and timestamps, hard expiry, hashed single-use worker claim, worker/job binding, heartbeat, and bounded safe usage/latency metadata. Do not copy raw provider responses, permanent keys, audio, or full transcripts into session history by default.

Only an owner/admin can start a potentially billable test. Query session/agent/provider through the authenticated membership-derived organization. Platform provider inheritance goes through the M2 authorized resolver, never arbitrary platform IDs supplied by a browser. Recheck current actor role, agent existence, credential/version, enabled/fresh catalog and exact compatible selection at worker claim. A stale result must not revive an ended/revoked session.

LiveKit room names/participant identities are generated by Laravel, one session per isolated room. Browser tokens are short lived and scoped to that room, microphone publication/subscription, without admin or metadata grants; room data is permitted for a caller-checked interrupt RPC, with worker text input disabled. Explicit worker dispatch occurs through a server API, not secret-bearing token metadata. Job metadata carries only a bounded one-use claim ticket and session/room binding, never permanent API keys or instructions. Worker requests require a separate server-only HMAC key, bounded timestamp and replay protection. Worker credential delivery is a deliberate authenticated server-to-server response, not a frontend API.

Termination ends browser tracks immediately and requests room teardown. Worker/provider lifetime is bounded independently of the browser, with periodic authority/expiry checks. Failure to delete a room is recorded as cleanup pending, not falsely called successful cleanup; retry/expiry operations must be documented. No hidden fallback, cross-tenant context, silent replay of old responses, or session resurrection on reconnect.

## Integration plan

1. Verify currently installed LiveKit Agents/plugin/browser API versions against official docs and installed source. Pin the versions used. Verify OpenAI Realtime endpoints, model/voice/turn/transcription/language controls, interruption/truncation behavior and reported metrics.
2. Add the minimal session schema, strict services/authentication, short-lived room grants, LiveKit provisioning/dispatch/termination and one-use worker claim. Run backend security/state tests before joining a real room.
3. Implement the one-provider worker with real SDK calls, provider VAD/turn detection, interruptible streaming/context, final/live transcripts and actual metrics, per-job isolation and cleanup. Test real SDK imports/contracts with isolated doubles, explicitly not live success.
4. Connect the browser playground through the real LiveKit client, retaining honest disabled/setup states when infrastructure/credentials are missing. Test actual browser permissions, CSRF, cancellation, cleanup, response/storage redaction and error handling. No production fake transport or sample transcript.
5. **Live gate:** on reachable infrastructure, enter real provider keys in the encrypted UI and configure LiveKit plus the worker. Demonstrate new spoken questions and generated replies, context recall, interruption/cancelled audio, mute/end, timeout/reconnect, second-session isolation and measured timing. Record sanitized evidence and update status. Do not claim real-time voice readiness without this test.
6. Only after the first spoken gate passes: implement additional providers and independently validated streaming modular STT/LLM/TTS factories, broaden language/voice/browser validation and production reliability/load review. Telephony remains a later milestone.

## Dependencies and risks

- A public browser-reachable LiveKit Cloud or properly deployed self-hosted LiveKit server (TLS/WebRTC/TURN as needed), project API key/secret, an independently running worker, secure Laravel → LiveKit and worker → Laravel HTTPS, and a funded inference-capable OpenAI project/key are prerequisites for spoken acceptance.
- This sandbox has Python 3.11, Node 22 and portable PHP 8.4, but no Go/Docker/LiveKit server. Its outbound allowlist excludes OpenAI and LiveKit hosts. The M2 provider database contains no saved credentials. Code/protocol/browser checks can run here; a genuine spoken trial requires reachable deployment infrastructure. Never request keys in chat or bypass the sandbox network restrictions.
- LiveKit/API model versions, input-transcription choices, language coverage and interruption APIs change. Documentation/SDK compatibility does not prove paid inference entitlement. Urdu/Hindi pronunciation, multilingual code switching and real turn quality must be evaluated with actual speech.
- Native realtime metrics differ from modular STT/LLM/TTS metrics. Label provider/worker timings separately from actual client transport/playback observations; show unavailable rather than inventing zero or promising 500–800 ms.
- Provider/LK SDK logs and cloud observability can retain secrets, transcripts or audio. Disable application audio recording/default content telemetry and sanitize dependency errors; document cloud/operator privacy settings. No global provider key environment variable is a substitute for per-session tenant-authorized key resolution.
- Short-lived JWT expiry does not disconnect an already joined participant by itself. Hard session limits, authoritative worker checks, explicit room deletion and stale-session cleanup are required.
- Production goals require later real-network load/chaos tests, MySQL/concurrency, TLS/proxy/TURN, other browsers/devices, credential rotation/worker crash/cleanup drills and independent security review. They are gates, not claims of this first slice.
